# Overview

TokenShell Riverpod adalah starter/reference template Flutter Material 3,
dibangun dengan Clean Architecture (feature-first) di atas stack Riverpod 3
codegen, go_router, dio + retrofit, freezed, fpdart, dan observability penuh
(Talker + Sentry). Posts adalah reference feature 4-layer penuh yang
dimaksudkan sebagai pola yang dicontoh setiap fitur baru; Home dan Settings
adalah placeholder presentation-only.

Per 24 Agustus 2026, proyek ini juga sudah dimigrasikan dari
`package:flutter/material.dart` ke `material_ui` (standalone design-system
package Flutter, v1.0.1) — mendahului deprecation resmi bundled
Material/Cupertino imports yang dijadwalkan mulai stable release Fall 2026
(sekitar November).

---

# Goals

- Starting point yang genuinely generic untuk proyek Flutter B2B baru — bukan patch dari proyek lama
- Observability production-grade sejak hari pertama (Sentry + Talker saling forward, bukan ditambah belakangan)
- Resilience jaringan yang matang (retry dengan backoff, connectivity-aware, offline banner) tanpa menunggu insiden produksi
- Setiap fitur baru mengikuti pola Posts secara mekanis (Domain murni, Either-based, keepAlive/autoDispose yang selalu beralasan)

# Layer Responsibilities

## App Layer
- Bootstrap `MaterialApp.router`, wiring `AppRouter`
- Fallback ThemeData jika `AppTheme` gagal build (dilaporkan via `talker`)
- Clamp `MediaQuery.textScaler` ke ceiling 1.6x sebelum diteruskan ke subtree

## Core / Network Layer
- `DioClient` — konfigurasi dasar + urutan interceptor
- `AuthInterceptor` — no-op sampai fitur auth ada, plus Sentry user-scope helper
- `RetryInterceptor` — jittered exponential backoff, menghormati header `Retry-After` (429 handling)
- `ConnectivityProvider`/`ConnectivityGuard` — two-tier check (adapter + reachability probe), TTL cache asimetris
- `OfflineProvider` — derived boolean untuk `AppShell`'s offline banner

## Core / Error Layer
- `Failure` hierarchy (Freezed union)
- `FailureMapper` — satu titik pemetaan `DioException`/`PlatformException` → `Failure`
- `fpdart Either<Failure, T>` dipakai konsisten dari Data sampai Presentation

## Core / Theme Layer
- `design_system/tokens/` — 10 file token (warna, radius, shadow, opacity, durasi, ikon, dst.)
- 5 `*ThemeBuilder` class (button, input, navigation, surface, feedback)
- `AppTheme` — merakit `ThemeData` dari token + builder, tanpa `useMaterial3` eksplisit (default sejak Flutter 3.16)

## Core / Routing Layer
- `ShellFeature` — menyatukan registrasi route + nav destination dalam satu deklarasi per fitur
- `FeatureRegistry.shellFeatures` — satu-satunya titik edit untuk menambah fitur shell-level baru
- Auth redirect masih placeholder (ditandai jelas sebagai companion task fitur login)

## Core / Observability Layer
- Sentry + Talker saling forward — setiap `talker.handle()` otomatis jadi event Sentry
- Bootstrap zone-safe via `Sentry.runZonedGuarded`
- Header sensitif (`Authorization`, `X-Api-Key`) permanent-redacted di semua flavor

## Core / DI Layer
- Riverpod Providers sebagai mekanisme DI, generated via codegen
- Keputusan `keepAlive` vs `autoDispose` selalu didokumentasikan dengan alasan konkret

## Feature Layer (pola Posts)
- Data → Domain → Presentation, Repository pattern dengan `fpdart Either`
- `PostsNotifier` — pagination + retention-window eviction (`_maxRetainedPages`), pola wajib dicontoh fitur paginated berikutnya

# Dependency Flow

```
Presentation → Domain → Data → External
      ↑              ↑
   Riverpod       fpdart Either
   Providers      (Result Type)
```

Aturan:
- Presentation HANYA bergantung pada Domain interfaces
- Domain TIDAK bergantung pada Data atau Presentation (100% pure Dart, tidak ada import Flutter)
- Data mengimplementasikan Domain interfaces
- `fpdart Either` digunakan di seluruh layer untuk error propagation

# Request Flow

```
UI Widget (posts_page.dart)
  → Riverpod Notifier (PostsNotifier — triggers use case)
    → GetPostsUseCase (business logic tipis)
      → PostRepository interface (domain contract)
        → PostRepositoryImpl (data layer, dibungkus ConnectivityGuard)
          → PostRemoteSource (Retrofit API call via Dio)
            → JSONPlaceholder API Response
          ← PostModel.fromJson (Freezed deserialization)
        ← Either<Failure, List<Post>> (dipetakan dari model)
      ← Either<Failure, List<Post>>
    ← Either<Failure, List<Post>>
  ← AsyncValue<PostsListState> (via Riverpod, termasuk pagination state)
UI Widget merender berdasarkan AsyncValue + isLoadingMore/hasMore
```

---

# Error Flow

```
Exception (network, parsing, server, secure-storage platform-channel)
  → Ditangkap di Repository Implementation
    → Dipetakan ke domain Failure via FailureMapper (mis. NetworkFailure, ServerFailure)
      → Dikembalikan sebagai Left(failure) via fpdart Either
        → Use Case meneruskan Either tanpa diubah
          → Riverpod Notifier expose sebagai AsyncError
            → UI Widget (AppStateView) menangani state error
              → User melihat pesan error / opsi retry
```

Dilog di setiap layer via Talker, otomatis ter-forward ke Sentry.

---

# State Management Flow

```
User Action (scroll to bottom / pull to refresh)
  → Widget memanggil method PostsNotifier
    → Notifier set state isLoadingMore = true
      → GetPostsUseCase dieksekusi
        → Hasil dikembalikan (Either<Failure, List<Post>>)
          → Notifier fold Either:
              Left(failure) → loadMoreError diisi
              Right(data)   → posts di-append, retention window dievaluasi
            → Widget rebuild berdasarkan PostsListState baru
```

State transitions: Loading → Data | Error. Tidak ada `setState` manual di luar guard `mounted`; semua state signifikan melalui Riverpod `AsyncNotifier`/`Notifier`.

# Important Decisions

| Decision | Reasoning |
|---|---|
| Migrasi ke `material_ui` (24 Aug 2026) | Flutter secara resmi men-decouple Material/Cupertino dari core SDK mulai 3.47; bundled import dijadwalkan mulai deprecated di stable release Fall 2026 (~November) — migrasi sekarang menghindari scramble nanti |
| Feature-First over Layer-First | Lebih mudah dinavigasi, isolasi lebih baik antar fitur |
| fpdart Either over exceptions | Error handling eksplisit, tidak ada throw tersembunyi |
| Riverpod Codegen | Type-safe, mengurangi boilerplate |
| `ConnectivityGuard` membungkus repository call | Menghindari round-trip sia-sia saat offline sudah diketahui, tanpa menyembunyikan error jaringan yang genuine |
| `AppStrings` sebagai single string source, bukan i18n penuh | Murah dilakukan sekarang selagi call site masih sedikit; jalur retrofit ke i18n nyata sudah didokumentasikan |
| Sentry + Talker saling forward | Satu titik pemanggilan log (`talker.handle()`) otomatis terlihat di kedua sistem |
| `CHANGELOG.md` menggantikan komentar bergaya audit inline | Histori perubahan yang genuinely terverifikasi butuh rumah append-only tunggal, bukan kode revisi semu tersebar di komentar sumber |

# Tradeoffs

| Tradeoff | Accepted Because |
|---|---|
| Lebih banyak boilerplate (Freezed, Retrofit, Riverpod codegen) | Maintainability jangka panjang > kecepatan jangka pendek |
| Pola pagination/retention `PostsNotifier` wajib dicontoh fitur berikutnya | Bug laten di sana akan tereplikasi ke banyak fitur — tapi menulis ulang per-fitur dinilai risiko yang lebih besar (lihat doc comment `posts_notifier.dart`) |
| `material_ui` dimigrasikan lebih awal dari sebagian besar ekosistem | Eksposur lebih tinggi terhadap bug early-adopter, diterima untuk menghindari scramble mendekati deprecation November 2026 |
| `flutter_secure_storage` wired tapi belum ada consumer | Biaya kecil di depan, menghindari seam yang lebih besar untuk di-wire nanti begitu fitur auth dibangun |

# Extension Guide

## Menambah Feature Baru
1. Buat folder `lib/features/[feature_name]/`
2. Buat struktur `data/`, `domain/`, `presentation/`, `di/`
3. Definisikan entity di `domain/entities/`
4. Buat repository interface di `domain/repositories/`
5. Implement repository di `data/repositories/` (bungkus dengan `ConnectivityGuard` jika perlu network call)
6. Buat use case di `domain/usecases/`
7. Buat Riverpod notifier di `presentation/notifiers/` — putuskan `keepAlive` vs `autoDispose` dan dokumentasikan alasannya
8. Buat UI di `presentation/pages/` dan `presentation/widgets/`
9. Definisikan `*ShellFeature` getter di `[feature_name]_routes.dart` (import `shell_feature.dart`, bukan `feature_registry.dart` langsung)
10. Daftarkan getter tersebut di `FeatureRegistry.shellFeatures` (`core/routing/feature_registry.dart`) — ini satu-satunya edit yang dibutuhkan untuk wiring route + nav destination sekaligus
11. Tambahkan string user-facing baru ke `AppStrings` — jangan hardcode literal di widget

## Menambah API Endpoint
1. Tambah method di Retrofit interface
2. Buat/update Freezed model untuk response
3. Update repository implementation
4. Tidak perlu mengubah domain layer jika contract tidak berubah

## Menambah Theme Token Baru
1. Tambah di `core/theme/design_system/tokens/` sesuai kategori (warna/radius/shadow/dll.)
2. Konsumsi lewat `*ThemeBuilder` atau `ThemeConstants` — jangan hardcode nilai di widget

# Testing Strategy

| Layer | Tool | Approach |
|---|---|---|
| Use Cases | flutter_test + mocktail | Mock repository, test business logic |
| Repositories | flutter_test + mocktail | Mock data source, test mapping model → entity |
| Notifiers | flutter_test + ProviderContainer | Test state transitions (Loading → Data \| Error) |
| Widgets | flutter_test | Golden tests + interaction tests |
| Integration | flutter_test | End-to-end flow testing |

`mocktail` dan `flutter_test` sudah terpasang sebagai dev dependency. Implementasi test aktual sengaja berada di luar scope review dan implementasi kali ini, sesuai permintaan eksplisit pemilik proyek.
